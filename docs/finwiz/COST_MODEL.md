# Finwiz cost model

The ₹50 Plus and ₹125 Pro monthly averages are planning targets. Application spending limits default to zero and require separately approved production settings. Paid inference is off by default.

Only users with a current live billing entitlement can use the paid lane. The reserve uses configured INR millionths per million input, output and reasoning tokens. The input estimate uses serialized bytes plus overhead. Output and reasoning each reserve the configured completion allowance. PostgreSQL checks UTC daily and monthly platform liability, each tier’s monthly liability and the user’s daily liability before dispatch. A timed-out, failed or otherwise unreported attempt keeps its reservation as unresolved spending. A complete matching breakdown is reconciled at the configured model rates. An estimate overrun records the larger reported cost, alerts operators and blocks further paid requests for that UTC month. Reconciliation reports observed usage at configured rates. Compare it with provider invoices and actual FX, taxes, processor fees, refunds and subscriber mix before approving price assumptions or production allowances.

| Provisioned control | Production setting |
| --- | --- |
| Paid project and model | `FINWIZ_PAID_GEMINI_API_KEY`, `FINWIZ_PAID_GEMINI_MODEL` |
| Model prices | `FINWIZ_PAID_INPUT_MICROS_PER_MILLION`, `FINWIZ_PAID_OUTPUT_MICROS_PER_MILLION`, `FINWIZ_PAID_REASONING_MICROS_PER_MILLION` |
| Platform budget | `FINWIZ_PAID_DAILY_MICROS`, `FINWIZ_PAID_MONTHLY_MICROS` |
| Plan and user budgets | `FINWIZ_PAID_PLUS_MONTHLY_MICROS`, `FINWIZ_PAID_PRO_MONTHLY_MICROS`, `FINWIZ_PAID_USER_DAILY_MICROS` |
| Provider request and token budget | `FINWIZ_PAID_REQUESTS_PER_MINUTE`, `FINWIZ_PAID_TOKENS_PER_MINUTE`, `FINWIZ_PAID_TOKENS_PER_DAY`, `FINWIZ_PAID_DAILY_ATTEMPTS` |
| Approval and emergency stop | Both `FINWIZ_PAID_ENABLED` and `FINWIZ_PAID_APPROVED` are required. Set `FINWIZ_PAID_ENABLED=false` and restart the backend. To stop new paid requests without restarting, an authorized database operator can run `UPDATE finwiz_spend_guard SET paused=true WHERE id=1;`. Revoke the paid project key for an immediate provider-side stop. |

Before authorizing this lane, confirm the distinct billing project, model terms, retention, provider-side enforcement and regional eligibility. Budget alerts and application reservations cannot cap charges generated by other apps, delayed upstream usage or provider pricing changes. Configure an enforceable upstream limit where available.
