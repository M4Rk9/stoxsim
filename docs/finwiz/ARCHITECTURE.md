# Finwiz F1 architecture
Existing authenticated ask -> server-selected depth -> verified context -> request allowance lease -> gateway -> Groq, Gemini, Cloudflare Workers AI, explicitly pinned OpenRouter free upstream -> completion validation -> atomic settlement -> existing response contract.
Every attempted network call is reserved in PostgreSQL before dispatch. Success increments one request counter; failure releases the allowance but still consumes operational attempts. Old aggregate attempts retained; new successful counts start at V137. Pending reservations expire after 120s. Daily UTC rollover. A 4x user attempt guard prevents repeated failure abuse; the F1 global attempt default was 500. Local cooldown and concurrency are per process; durable daily counters survive restart. No same-provider immediate retries. Do not confuse application caps with upstream quotas.
No new paid inference path. New providers require explicit confirmation of free capacity. The confirmation is an operator assertion, not provider billing enforcement. OpenRouter requires explicit :free model and distinct upstream, no automatic upstream fallback, zero price cap and data_collection deny. Validate actual provider terms and models before activation. Current provider parsing rejects safety refusals and incomplete candidates; does not certify financial factual accuracy.

## Final F1 safeguards
V138 rolling admission events count estimated tokens (serialized UTF-8 bytes + two completion budgets + 256 overhead); attempt and token reservations are never refunded. Default Gemini 10 requests/min, 40000 estimated tokens/min, 1000000/day; other providers 5/min, 8000 estimated tokens/min, 180000/day. These are application ceilings, not provider limits. The dispatch network deadline (25 seconds by default) covers full-body reads with cancellation, not upstream market-context retrieval or DB latency. V139 deduplicates optional client-generated UUIDs per authenticated user for roughly 24–48 hours without storing prompts/answers; repeated key yields conflict, not response replay. Each deliberate new submission uses a new key. Production preflight validates at least one enabled provider independently. F2 remains responsible for isolated paid capacity and monetary budgets.

## F2 admission and billing

Server-resolved depth selects separate request, token and local semaphore pools. Defaults reserve 25% each for Plus and Pro, with the balance available to Free. When a small quota cannot support every tier, Pro receives the first slot and Plus receives the next. Tier capacity is not borrowed. A fair queue waits up to 100 ms per provider before moving to the next candidate. Paid tiers favor free providers with larger configured token capacity, then may use a separately configured paid Gemini project. Failover stays within the request deadline and never repeats an immediate call to the same provider. A cooled provider allows one recovery attempt at a time per application process.

The platform and provider daily counters continue to count historical attempts. On rollout, attempts recorded before V141 still count against the shared upstream ceiling and can temporarily reduce every tier’s available headroom until the next UTC day. Admission locks span the rolling rate window across UTC midnight. Per-process concurrency assumes the current single API instance. Multiplying replicas would multiply local concurrent slots, while the PostgreSQL request and token limits remain shared.

V140 captures agreement terms. V141 adds tier-scoped admission data. V142 preserves monetary liability across timeouts and accounts for failed or unknown billing responses. Settlement uses provider-reported input, output and reasoning tokens with configured prices. The admin endpoint `GET /api/v1/admin/analytics/learning` returns aggregate `paidInference` lines by provider, model and tier. Circuit metrics contain fixed provider/result labels. Learner-facing messages continue to distinguish capacity limits and provider unavailability.
