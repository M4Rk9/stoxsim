# Finwiz F1 architecture
Existing authenticated ask -> server-selected depth -> verified context -> request allowance lease -> gateway -> Groq, Gemini, Cloudflare Workers AI, explicitly pinned OpenRouter free upstream -> completion validation -> atomic settlement -> existing response contract.
Every attempted network call is reserved in PostgreSQL before dispatch. Success increments one request counter; failure releases the allowance but still consumes operational attempts. Old aggregate attempts retained; new successful counts start at V137. Pending reservations expire after 120s. Daily UTC rollover. A 4x user attempt guard prevents repeated failure abuse; global attempt default 500 remains for F1, isolated paid capacity is F2. Local cooldown and concurrency are per process; durable daily counters survive restart. No same-provider immediate retries. Do not confuse application caps with upstream quotas.
No new paid inference path. New providers require explicit confirmation of free capacity. The confirmation is an operator assertion, not provider billing enforcement. OpenRouter requires explicit :free model and distinct upstream, no automatic upstream fallback, zero price cap and data_collection deny. Validate actual provider terms and models before activation. Current provider parsing rejects safety refusals and incomplete candidates; does not certify financial factual accuracy.
